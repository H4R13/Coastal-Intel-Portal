# PCOP, Pakistan Coastal Observation & Projection (formerly Nereus Sentinel / Coastal Hazards 2): project notes for Claude

React (Vite) + Node portal for the coast of Pakistan: map layers (MapLibre), a year timeline, charts, and a chat assistant.
Same server, API and database as the original portal. Read README.md first; this file is what is not obvious from the code.

## Run it
- `npm install`, then `npm start` (builds into dist/ and serves http://localhost:5173). `npm run dev` rebuilds on change.
- Needs PostgreSQL + PostGIS and (optionally) Redis/Memurai; settings in `.env` (see `.env.example`).
- PostgreSQL on the laptop (2026-10-26, owner request): `npm run dev` starts it first unless it already answers, through `pg_ctl` under the user's own account (`server/pg.mjs`, no admin rights); it runs in a hidden console of its own (PowerShell `Start-Process`; merely detached, it still got the terminal's Ctrl+C and died with 0xC000013A), so Ctrl+C on dev leaves it running, `npm run db:stop` ends it (`db:start`, `db:status` too). Its start-up log is `.pg/pg_ctl.log`; never put it in the data folder (after an unclean stop the server stalls 30 s on that open file). The Windows service `postgresql-x64-18` should be Manual, not Automatic (owner kills it from Task Manager before gaming; a killed server recovers by itself on the next start). The API answers 503 "Database unavailable" when it is down.
- Data loaders: `npm run load:mangroves|erosion|ocean|amib|dmjm|nutrients`. `npm run build` after any change in `src/`; the server serves dist/.
- Never commit `.env`, `Other Data/` (raw team data, ~65k files), `data/` or the caches. They are set up per machine.

## The assistant: decisions already made (do not re-litigate)
- It is called **Hela** (`NAME` in `chat.mjs`; the UI text is in `Assistant.jsx`). "Hey Hela, ..." addresses it: the name is stripped from the question first.
- **The local model does not write figures.** Measured on hermes3:8b (2026-10-07/08): given correct facts in three different forms it still moved numbers between flow scenarios, blended two statements into one, and listed effects (livestock, fish catch) that are not in the data. So the order in `chat()` is: small talk → `answerDirect()` in `answers.mjs` (sentences written from the database, shown as they are, no model call) → `route()` (the model only names the topic of a question whose words matched nothing, in a fixed JSON format, about 2 s) and `answerDirect()` again → text search, which only reports where the word turns up, or that the portal has nothing on it. No answer text is written by the local model any more: asked to explain search snippets it attached a neighbouring record's figure to the wrong fish.
- **Exception, her own views (2026-10-16, the user asked for opinions):** a question asking for Hela's view, advice or ideas ("what do you think of the layout?", "should we worry about salinity?", and "why?" right after one) goes to `opinion.mjs` before `answerDirect()`. The model writes the view from a fixed description of the portal (`PORTAL`, written from the components and the tour; keep it true when the UI changes) and, when a subject is named or carried over, the figures from `answerDirect()`, which are shown first; the view follows as "My view (not from the data):". Guards in `clean()`: every sentence with a digit is dropped, so are effects or causes the given facts do not name (`EFFECTS`), unfinished sentences and "as an AI" disclaimers; `trends()` tells the model which figures go up and which go down. Eval cases with `opinion: true` check this (skipped by `--direct`). With the model unreachable, `design()` in `answers.mjs` says so.
- **Conversation, date and news (2026-10-29, owner request: "I can't talk to her like I do to you … no more 'it's not in my database'"):** this relaxes the old dead-end replies, not the rule on figures. (1) `quick()` in `converse.mjs` answers the date/time and "what's new / since you were updated" in code (`WHATS_NEW` is her list of abilities: keep it true; she says she was NOT retrained). (2) `news.mjs`: "what's new today in coastal hazards" fetches Google News RSS (public feed, 30 min cache, search words only, `OFF_TOPIC` filter), lists headlines verbatim with outlet, date and link, never rewritten by the model. (3) When no dataset matches and the text search finds nothing worth reporting, `viaOllama` now calls `converse()` (free chat, temperature 0.6, today's date and `WHATS_NEW` in the prompt, told to quote no portal numbers and not to claim it knows today's news); an answer containing a digit gets "(General knowledge, not from the portal's data.)". Portal data questions still go to `answerDirect()` first and keep their exact, sourced figures. Not yet re-run: the full model eval (`npm run hela:eval`) after this change.
- **Automatic data updates (2026-10-29, owner request: "auto update the data from the network", phase 1):** `server/external.mjs` (registry `SOURCES`, one entry per documented public API) and `npm run update:data` (`server/update-data.mjs`). Pipeline: fetch → checks (counts, ranges, duplicates, "did not shrink >5 %") → staged in `ext_staging` with a diff against what is promoted → **a person approves** (`-- --approve=N`; `--reject=N`; `--force` only for a batch that failed its checks) → promoted into the source's own table (`ext_quake`) in one transaction, cache `external:*` cleared. `-- --fetch` stages only and is safe to schedule weekly; approval is never automatic. Only USGS earthquakes exist so far (M≥4 since 1973, box lat 21-27.5 lon 60-70, 468 events; the CLAUDE.md "earthquakes not loaded" gap is closed once a batch is approved, tsunami and shelf bathymetry still are not). Hela (`quakes()` in `answers.mjs`) writes the figures from `ext_quake` and labels them "External data (USGS, not the team's)" with fetch date; the model never writes them. The team's data (AMHK, DMJM, AMSK) is never fetched or overwritten by this. Second source `psmsl-karachi` (PSMSL RLR monthly, station 204 = Karachi, `https://psmsl.org/data/obtaining/rlr.monthly.data/204.rlrdata`, 692 months 1916-2016, table `ext_tide`, `tide()` in `answers.mjs`, refresh 30 days; the file ends in 2016 so it will rarely change). It sits beside the team's own Karachi gauge (`amib:series/D`, which says a reference-level break is suspected); the external answer repeats that caveat and the two are not merged. Each source in `SOURCES` carries its own `parse/checks/current/save/held`. Literature watcher: `npm run watch:papers` (`server/watch-literature.mjs`, `TOPICS` = 8 searches, table `lit_watch`) records papers not seen before and prints a 30-day digest; it only lists them (not shown to Hela or on the map); first run (62 papers) was the baseline. Known limit: `searchPapers` ranks by citations and keeps the top 8 per topic, so a brand-new, uncited paper may not surface yet. Next planned: Copernicus/GMW (need accounts), cross-reference jobs, a literature watcher.
- **Investigations (2026-10-29, owner request: "make its own inferences and confirm them through research papers"):** `research.mjs`, tried before the opinion branch in `chat()`. A question asking for hypotheses, theories, evidence or "what do the papers say" ("investigate the mangrove trend", "what could explain the saline intrusion?") gets: the data's figures first (`answerDirect`, as always); up to 3 hypotheses from the model in a fixed JSON format (no digits, labelled as hers); real papers from OpenAlex (`literature.mjs`, free, no key, cached a week in `literature_cache`; only the search words leave the machine; `RESEARCH_ONLINE=0` switches it off); then per abstract the model returns a stance plus ONE sentence, and code keeps the stance only if that sentence occurs word for word in the abstract and shares ≥2 content words with the hypothesis. Only papers whose abstract names this region (`LOCAL`) count towards the verdict; others are listed as "elsewhere". The verdict is counted by code ("supported by 2 of the 4 papers read", "contested", "no support found"), never "confirmed", and the answer ends by saying abstracts are not proof. Measured: ~15 s per investigation on the RTX 5050 PC. It is not training: no weights change; the model is boxed in the same way as `opinion.mjs`. Known limits: hermes3:8b proposes generic hypotheses and is generous with "supports" (hence the two gates); it reads abstracts only, not full papers; it does not yet test a hypothesis against the portal's own series (a correlation between two loaded series would be the next step). Eval cases `rs-*` (`research: true`, skipped by `--direct`).
- To teach Hela a new kind of question: add the sentence to the topic's function in `answers.mjs`, add a case to `eval-cases.mjs`, run `npm run hela:eval -- --direct` (no server, seconds) and then the full `npm run hela:eval` against the running portal. The full eval needs a server started with `ASSISTANT_PER_MINUTE=1000` (e.g. a second copy: `PORT=5174 ASSISTANT_PER_MINUTE=1000 node server.mjs`, then `npm run hela:eval -- --url=http://localhost:5174`; options take `=`). `npm run hela:review` lists thumbs-down answers and the questions that still went to the model.
- Answers are concise by default (the user asked for this): the sentence that answers, plus one more only for comparisons and lists; `also` lines appear only when the user asks for detail ("in detail", "tell me more"); "short" gives the answer alone. The rule is at the end of `answerDirect()`.
- Each topic function returns `{ say, also, covers }`: `say` answers what was asked (most direct first), `also` is extra context, `covers` lists what the data can explain (causes, effects, solutions, why it matters). Asked for one it cannot explain, Hela says so before the figures. Where the data runs out, the sentence says so (a place with no station, a year before the record, causes that are not held).
- **Two mangrove datasets disagree** and Hela says so: the mangrove layer's table (`mangrove_area`: 406 km² in 1988 → 848 km² in 2025, rising) and the saltwater package's GMW v3 extents by zone (`amib:series/F`: zones total 1,119 km² in 1996 → 864 km² in 2020, falling). Nobody has reconciled them; do not pick one silently. Since 2026-10-21 the UI no longer shows the package's mangrove maps (owner request: the Coastal Hazards "Mangrove cover" hazard is gone and `browsable()` in `amibData.js` hides them from the raw browser); Hela still cites them.
- The mangrove "Gain / loss" chart (`GainLossChart.jsx`) reads `mangrove_gainloss`, loaded from `Other Data/AMSK/Mangrove year layers/mangrove_by_year_1985_2050.csv` by `npm run load:mangroves -- --gain-loss` (that file only, seconds).
- Call mode (voice): `Chat` in `Assistant.jsx` runs the loop listen → ask (`voice: true`, short answer + `spoken` text) → say → listen. Hearing is the browser's SpeechRecognition (it asks for 5 guesses and takes the first naming a portal word, `PORTAL_WORDS`; `HEARD` in `understand.mjs` fixes what still comes through misheard); speaking is ElevenLabs via `POST /api/assistant/speak { id }` (`voice.mjs`, key in `.env`, only stored answers are spoken) or the browser's speechSynthesis when no key is set. Not yet tested with a real microphone or a real ElevenLabs key (2026-10-08); cutting in is by tap, not by voice, because the microphone would hear her own speech.
- Follow-ups: `subject()` in `understand.mjs` carries the earlier questions' topic when the new one names none and points back ("why is that?", "and by 2050?", "make it shorter"); a new unrelated question does not inherit it.
- Never put regex backslashes through a shell heredoc or `node -e` when patching these files: they were silently stripped several times (`\b` became a backspace character). Use the Edit tool, or write a script file with the Write tool.
- The office PC has no graphics card (Intel UHD only): hermes3:8b writes about 8.5 tokens a second whatever the thread count; more threads only speed up reading the prompt (`OLLAMA_THREADS`). A model-written answer takes 20-80 s, which is the other reason answers come from `answers.mjs`.
- It is NOT a trained/fine-tuned model. Feedback (👍/👎) is stored in `assistant_feedback` and used to improve the sentences and the look-ups, not weights.
- Default provider is a local open model through Ollama (no API key, no per-question cost). Claude via `ANTHROPIC_API_KEY` is an optional upgrade and skips `answers.mjs` (it calls the tools itself).
- Not in the database, so it must say "not loaded": earthquake/seismic records, continental-shelf depth change, raw Google Earth Engine exports. Adding them is future work (USGS catalogue, bathymetry, GEE exports).
- General science (e.g. plankton and oxygen) beyond the data: answered only through the investigation mode above (cited papers); there is still no stored reference library. The glossary in `answers.mjs` defines only the portal's own terms (psu, MAF, EEZ, SSP, aragonite ...).
